# Дипломный проект «1С-программист: с нуля до middle»

## Кастомизация конфигурации «Управление IT-фирмой» для компании «Ваш компьютерный мастер»

В конфигурацию добавлены две подсистемы:

- **Работа с заявками клиентов** — абонентские договоры, документ «Обслуживание клиента», оповещения в Telegram, автозаполнение и печать акта в «Реализации товаров и услуг», массовое создание актов.
- **Расчёт управленческой зарплаты** — условия оплаты сотрудников, начисление зарплаты (оклад, процент от работ, отпуск, НДФЛ), премии, выплата зарплаты, график отпусков.

Все добавленные объекты имеют префикс `ВКМ_` и находятся в подсистеме **ВКМ_ДобавленныеОбъекты** (разделы «Обслуживание клиентов» и «Управленческая зарплата»). Изменения в типовых объектах выделены комментариями `// ВКМ Начало` / `// ВКМ Конец`.

- Исходный код конфигурации в формате 1С:EDT — каталог `fonecmid-diplom`.
- Демонстрационная база (`*.dt`) — в разделе **Releases** репозитория.
- Сценарий автотеста и инструкция по его запуску — каталог `tests`.

## Инструкция по начальной настройке

Инструкция предназначена для специалистов заказчика. Она описывает, что нужно сделать в информационной базе, в которой уже ведётся учёт в исходной конфигурации, чтобы начать пользоваться новой функциональностью.

### 1. Обновление конфигурации

1. Сделайте резервную копию информационной базы (Конфигуратор → *Администрирование* → *Выгрузить информационную базу*).
2. Обновите конфигурацию базы до версии из этого репозитория (версия конфигурации **1.0.1.7** или выше) и примите изменения структуры базы данных.
3. Запустите программу в режиме 1С:Предприятие **под пользователем с полными правами** (администратором).
4. Дождитесь окончания обработки *«Обновление версии программы»*. При обновлении автоматически создаются и обновляются поставляемые профили групп доступа (см. п. 7).

> Если поставляемые профили были изменены разработчиком, обновление профилей в базе выполняется только при повышении номера версии конфигурации. Поэтому при каждом изменении ролей или профилей в коде нужно увеличивать версию конфигурации.

### 2. Включение команды «Все функции»

Константы задаются через меню *«Все функции»*:

1. Меню **≡** → **Сервис и настройки** → **Параметры**.
2. Включите флажок **«Отображать команду "Все функции"»** → **Применить**.

### 3. Номенклатура для актов

В справочнике **Номенклатура** создайте (или выберите существующие) две услуги:

| Назначение | Пример наименования |
|---|---|
| Абонентская плата | «Абонентское обслуживание» |
| Работы специалиста (почасовые) | «Работы специалиста» |

### 4. Константы

Меню **Все функции** → **Константы** — заполните:

| Константа | Что указать |
|---|---|
| **Номенклатура абонентская плата** (`ВКМ_НоменклатураАбонентскаяПлата`) | услугу абонентской платы из п. 3 |
| **Номенклатура работы специалиста** (`ВКМ_НоменклатураРаботыСпециалиста`) | услугу почасовых работ из п. 3 |
| **Токен телеграм бота** (`ВКМ_ТокенТелеграмБота`) | токен бота (см. п. 5) |
| **Идентификатор группы телеграм** (`ВКМ_ИдентификаторГруппыТелеграм`) | ID группы для оповещений (см. п. 5) |

Без заполненных констант номенклатуры не будут работать автозаполнение «Реализации товаров и услуг» и обработка массового создания актов (будет выдано сообщение об ошибке).

### 5. Оповещения в Telegram

1. В Telegram создайте бота через **@BotFather** (команда `/newbot`) и скопируйте выданный **токен**.
2. Создайте группу для специалистов и добавьте в неё бота.
3. Узнайте идентификатор группы (например, напишите в группу любое сообщение и откройте в браузере `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — значение `chat.id`, обычно отрицательное число).
4. Укажите токен и идентификатор в константах (п. 4).
5. Проверьте, что регламентное задание **«Отправка уведомлений телеграм»** включено: **Администрирование** → **Обслуживание** → **Регламентные операции** → **Регламентные и фоновые задания**.

При записи документа «Обслуживание клиента» (новая заявка, изменение специалиста, даты или времени) в справочник **Уведомления телеграм-боту** добавляется сообщение. Регламентное задание отправляет сообщения в группу и удаляет успешно отправленные.

> В файловом варианте базы регламентные задания выполняются, пока запущен хотя бы один сеанс 1С:Предприятия.

### 6. Абонентские договоры

Для каждого клиента на абонентском обслуживании в справочнике **Договоры контрагентов**:

1. Установите **Вид договора** = **«Абонентское обслуживание»**.
2. Заполните появившиеся поля: **Дата начала действия**, **Дата окончания действия**, **Сумма абонентской платы** (в месяц), **Стоимость часа работы**.

Документ «Обслуживание клиента» проводится только по договору вида «Абонентское обслуживание» и только если дата документа входит в период действия договора.

### 7. Пользователи и права доступа

В программе есть поставляемые профили групп доступа:

| Профиль | Для кого | Что доступно |
|---|---|---|
| **ВКМ Специалист** | специалисты | документы «Обслуживание клиента» (закрытие заявок, выполненные работы, файлы), отчёт «Выработка специалистов» |
| **ВКМ Менеджер** | менеджеры | планирование заявок (документ «Обслуживание клиента»), контрагенты, документы продажи |
| **ВКМ Бухгалтер** | бухгалтеры | обработка «Массовое создание актов», документы продажи, отчёт «Анализ выставленных актов» |
| **ВКМ Кадровик-расчетчик** | кадровики-расчётчики | условия оплаты, начисление зарплаты, премии, выплата, график отпусков, отчёты «Расчеты с сотрудниками», «Расход запланированных отпусков», «Выработка специалистов» |

Назначение прав:

1. **Администрирование** → **Настройки пользователей и прав** → **Пользователи**.
2. Откройте пользователя → кнопка **Права доступа** → отметьте нужный профиль → **Записать**.
3. Пользователю нужно перезайти в программу.

### 8. Расчёт зарплаты

В качестве сотрудников используются элементы справочника **Пользователи**.

1. **Условия оплаты сотрудников** (раздел *Добавленные объекты* → *Управленческая зарплата*): для **каждого** сотрудника введите запись с датой начала действия, **окладом** и **процентом от работ** (для административного персонала — 0).
   > Важно: если специалисту на дату обслуживания не задан процент от работ, документ «Обслуживание клиента» не проведётся. Нулевой процент допустим.
2. **График работы** заполняется автоматически (пятидневная рабочая неделя) при проведении документа «Начисление зарплаты».
3. Порядок работы в месяце:
   - **Начисление зарплаты** — строки «Оклад» за месяц по каждому сотруднику и «Отпуск» с датами отпуска; процент от работ и НДФЛ рассчитываются автоматически;
   - **Начисление фиксированных премий** — при необходимости, НДФЛ рассчитывается автоматически;
   - **Выплата зарплаты** — кнопка **«Заполнить по остаткам»** заполняет суммы задолженности на дату документа.
4. Отпускные рассчитываются от начислений за 12 предыдущих месяцев. Если начислений в программе ещё нет, отпускные будут равны нулю — для корректного расчёта введите начисления за предыдущие месяцы (или начинайте учёт с начала года).

### 9. График отпусков

В начале года кадровик вводит документ **«График отпусков»** на год. Сотрудники, у которых суммарно больше 28 дней отпуска, подсвечиваются. Кнопка **«Анализ графика»** открывает диаграмму Ганта с отпусками сотрудников.

### 10. Ежемесячная работа с заявками

1. **Менеджер** создаёт документ **«Обслуживание клиента»**: клиент, договор, специалист, дата и время работ, описание проблемы. Специалисты получают оповещение в Telegram.
2. **Специалист** после выполнения работ заполняет табличную часть «Выполненные работы» (фактические часы и часы к оплате), прикрепляет скан листа учёта рабочего времени и проводит документ.
3. **Бухгалтер** в начале месяца открывает обработку **«Массовое создание актов»**, выбирает месяц и создаёт акты (документы «Реализация товаров и услуг») по всем абонентским договорам. Повторно акт за тот же месяц по договору не создаётся. Печатная форма акта — в документе «Реализация товаров и услуг» (кнопка *Печать* → *Акт об оказанных услугах*).

### 11. Отчёты

Все отчёты строятся по данным регистров и имеют параметр периода.

| Отчёт | Раздел | Кому доступен |
|---|---|---|
| Выработка специалистов | Обслуживание клиентов / Управленческая зарплата | специалисты, кадровики |
| Анализ выставленных актов | Обслуживание клиентов | бухгалтеры |
| Расчеты с сотрудниками | Управленческая зарплата | кадровики |
| Расход запланированных отпусков | Управленческая зарплата | кадровики |

> Отчёт «Анализ выставленных актов» использует регистр выставленных услуг, который заполняется при проведении «Реализации товаров и услуг». После обновления конфигурации **перепроведите** ранее созданные документы «Реализация товаров и услуг», чтобы они попали в отчёт.
